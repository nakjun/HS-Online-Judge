# Python Judge

Python 코드 직접 실행과 예제 문제 채점을 지원하는 작은 웹앱입니다. 서버는 이 PC에서 돌아가고, 제출 코드는 Docker 컨테이너에서 실행됩니다.

## 원클릭 설치 및 실행 (Windows)

저장소를 ZIP으로 내려받아 압축을 푼 뒤 **`install.cmd`를 더블클릭**합니다. 스크립트는 Python 3.10 이상과 Docker Desktop을 확인하고, 없으면 `winget`으로 설치합니다. 이어 `.venv`에 Python 패키지를 설치하고 채점용 Docker 이미지를 준비한 뒤 실제 코드 실행을 검사합니다. 성공하면 LAN 서버를 시작하고 브라우저를 엽니다. 같은 스크립트를 다시 실행해도 기존 서버가 있으면 그대로 사용합니다.

처음 Docker Desktop을 설치한 경우 초기 설정이나 WSL 2 설치, Windows 재시작이 필요할 수 있습니다. 이 단계가 요청되면 완료한 뒤 `install.cmd`를 다시 실행하세요. 같은 LAN의 다른 기기에서 접속이 안 되면 Windows 개인 네트워크 방화벽에서 TCP 8000번 포트를 로컬 서브넷에 허용해야 합니다. 서버 출력과 오류는 `runtime/`에 저장됩니다.

Docker 확인 단계에서 `cannot find registry key`가 보이면 Docker Desktop 창을 열어 초기 설정을 마친 뒤 다시 실행하세요. 설치 스크립트가 Docker Desktop 창을 표시하고 엔진을 기다리도록 되어 있습니다. 계속 실패하면 설치 창에 표시된 전체 오류 문구와 Docker Desktop 설치 여부를 확인해야 합니다.

수동 실행은 Docker Desktop Linux 엔진을 켠 뒤 `python -m pip install -r requirements.txt`, `docker pull python:3.13-alpine`, `python server.py` 순서로 진행합니다. 기본 주소는 <http://127.0.0.1:8000>입니다.

설치 후 평소에는 **`run.cmd`를 더블클릭**하거나 `powershell -ExecutionPolicy Bypass -File .\run.ps1`로 실행합니다. 패키지를 다시 설치하지 않고 Docker 상태·채점 이미지를 확인한 뒤 LAN 서버를 실행합니다. 이미 실행 중이면 기존 서버를 사용합니다. `-NoBrowser`는 브라우저 자동 열기를 끄고, `-LocalOnly`는 이 PC에서만 접속하도록 새 서버를 시작하며, `-Port 8001`로 포트를 지정할 수 있습니다.

`git pull` 후에는 **`run.cmd -Restart`**로 서버 코드를 다시 불러오고 브라우저를 새로고침하세요. 재시작은 이 프로젝트의 절대 경로로 실행된 Python 서버만 종료합니다. 예전 설치 스크립트로 실행한 서버는 경로를 확인할 수 없어 자동 종료하지 않으므로, 기존 서버를 실행한 창을 닫고 `run.cmd`로 다시 시작하세요. 서버 로그는 `runtime/server.out.log`, `runtime/server.err.log`에 저장됩니다. 새 정답 코드 조회 API가 없거나 일시적으로 실패해도 문제 목록은 표시하며, 목록 위에 동기화 오류를 안내합니다.

## 관리자 화면

<http://127.0.0.1:8000/admin>에서 주차와 문제를 추가할 수 있습니다. 관리자 토큰은 `AS006`으로 고정되어 있습니다.

관리자 화면은 왼쪽 메뉴에서 수업 코드, 학생 명단, 제출 현황, 최근 제출, 주차, 문제를 각각 열 수 있습니다. 한 번 로그인하면 같은 브라우저의 로컬 저장소에 관리자 인증값이 보관되어 새로고침 후에도 유지됩니다. 공용 PC에서는 **관리자 로그아웃**을 누르세요.

문제에는 공개 예제와 채점 테스트 케이스를 각각 추가합니다. 각 케이스는 표준 입력과 예상 표준 출력으로 구성됩니다. 채점 테스트는 일반 문제 API에서 숨겨지며, 저장된 내용은 `weeks.json`과 `problems.json`에 남습니다. 기존 문제는 1주차에 표시됩니다.

관리자 화면의 **학생 명단 가져오기**에서 `.xlsx` 파일을 업로드할 수 있습니다. 첫 행에 `학번`, `이름` 열이 있어야 합니다. 기존 학번은 이름을 갱신하고 파일에 없는 학생은 유지합니다. 학번 앞자리의 0을 보존하려면 엑셀에서 학번 열을 텍스트로 저장하세요. 학생과 제출 기록은 `judge.db`에 저장됩니다.

학생은 학번, 이름, 수업 코드로 로그인한 뒤 주차별 문제를 풉니다. 초기 수업 코드는 `AS006`이며 관리자 화면의 **수업 코드 관리**에서 변경할 수 있습니다. 코드는 DB에 해시로 저장되고 변경하면 기존 학생 세션이 종료됩니다. 로그인 성공 후 30일 동안 사용할 수 있는 HttpOnly 세션 쿠키가 발급되고, 로그아웃하면 서버에서 세션이 삭제됩니다. `.py` 파일을 선택하거나 코드를 직접 입력할 수 있습니다. 정답 판정을 받은 문제는 목록에 체크마크가 표시됩니다. 관리자 화면의 **최근 제출**에 결과가 표시됩니다. 공유 수업 코드와 학번·이름만으로는 강한 본인 인증이 되지 않으므로 성적 확정 용도로 쓰려면 별도 로그인 방식을 추가해야 합니다.

학번과 이름은 같은 브라우저의 로컬 저장소에 보관되어 다음 로그인 때 채워집니다. 공용 PC에서는 **로그아웃** 후 **저장된 정보 지우기**를 누르세요. 관리자 화면의 **주차별 제출 현황**에서 학번 또는 이름으로 검색하고, 주차 칸을 눌러 문제별 제출·정답 상태를 볼 수 있습니다.

코드 편집기는 **Ctrl + # (Ctrl + Shift + 3)**으로 현재 줄이나 선택한 여러 줄의 주석을 넣고 뺄 수 있습니다. 작성 중인 코드는 학생·문제별로 브라우저에 자동 저장되어 문제 전환과 새로고침 후에도 유지됩니다. 정답 판정을 받은 제출 원문은 별도로 보관하며 **정답 코드 복원**으로 불러올 수 있습니다. 작성 중인 코드와 정답 코드는 따로 관리되므로 채점 중에 수정한 코드가 정답 원문을 덮어쓰지 않습니다. 브라우저 저장소가 비어 있으면 서버에 저장된 해당 학생의 마지막 정답 코드를 불러옵니다.

정답을 맞춘 문제를 선택하거나 다시 누르면 **서버에서 조회한 최신 정답 제출 원문을 우선 표시**합니다. 해당 문제의 브라우저 임시 코드보다 정답 코드가 우선하며, 로그인 후 처음 문제를 열거나 페이지를 새로고침할 때도 같은 규칙을 적용합니다. 아직 정답을 맞추지 못한 문제는 기존 임시 코드를 복원합니다. 문제를 편집하는 도중 자동으로 목록을 갱신할 때는 현재 편집 내용을 유지하고, 문제를 다시 선택하면 정답 코드를 표시합니다.

관리자 **주차별 제출 현황**에서는 드롭다운으로 조회할 주차를 선택합니다. 학번·이름·제출수·정답수 열 제목을 누르면 오름차순·내림차순으로 정렬됩니다. 제출수는 해당 주차의 총 제출 횟수이며 정답수는 정답 판정을 받은 서로 다른 문제 수입니다. 정렬은 전체 검색 결과에 적용된 뒤 100명씩 표시됩니다.

디자인 색상과 컴포넌트 규격은 [DESIGN.md](DESIGN.md)에 정리했습니다.

제출할 때 브라우저가 코드 편집기의 입력 이벤트를 기록합니다. 한 번에 붙여 넣은 문자가 최종 코드의 90% 이상이고 20자 이상이면 **전체 붙여넣기**로 표시합니다. 일부 붙여넣기, 직접 입력, 파일 업로드, 확인 불가도 구분합니다. 이 정보는 브라우저에서 보내므로 우회할 수 있고, 붙여넣기 여부가 LLM 사용 여부를 증명하지는 않습니다.

문제를 열어 둔 동안의 `visibilitychange`와 창 `blur`/`focus` 이벤트도 학생·문제별로 브라우저에 누적합니다. 제출 버튼을 누른 시점의 탭 숨김·포커스 이탈 횟수, 각 지속 시간, 두 상태의 중복을 제외한 화면 이탈 횟수·시간, 최근 100개 이벤트 발생 시각을 해당 제출에 고정해 저장합니다. 문제를 전환하거나 페이지를 닫은 이후의 시간은 이전 문제에 누적하지 않습니다. 작성 코드와 함께 기록을 복원하므로 새로고침 후에도 앞서 관찰한 집계는 유지됩니다. 관리자 **최근 제출 → 보기**에서 요약과 이벤트를 확인할 수 있고 이전 제출은 **미수집**으로 표시됩니다. 브라우저가 보고한 참고 정보이며 다른 탭의 주소·제목·내용은 수집하지 않습니다. 탭 이동과 다른 프로그램 사용을 확정적으로 구분할 수 없습니다.

학생 화면에서 현재 문제의 이탈 횟수·시간을 확인할 수 있으며, 브라우저 이벤트 외에 1초 간격으로 현재 상태를 점검합니다. 제출 결과에 **화면 활동 저장됨**이 표시되어야 서버 기록이 저장된 것입니다. 저장 확인이 안 되면 서버를 재시작하고 학생 화면을 새로고침한 뒤 다시 제출하세요. 관리자 최근 제출 목록은 해당 화면이 보이는 동안 10초마다, 화면에 다시 돌아왔을 때 자동 갱신되며 **제출 목록 새로고침**으로 즉시 조회할 수도 있습니다.

## 동작

- **실행:** 코드와 표준 입력을 보내 표준 출력, 오류 출력, 종료 상태를 확인합니다.
- **문제 채점 (코드 제출):** `problems.json`의 테스트 케이스를 순서대로 실행합니다. 정답, 오답, 실행 오류, 시간 초과 등을 반환합니다. 테스트 입력과 정답은 API에서 노출하지 않습니다.
- 테스트별 실행 제한: 6초(컨테이너 시작 시간 포함), 메모리 128MB, CPU 0.5개, 프로세스 32개, 출력 스트림별 64KB. 동시 제출은 2개까지 허용합니다.

## 접속 설정

기본 주소는 `127.0.0.1:8000`으로 이 PC에서만 접속됩니다. 다른 기기에서 접속하려면 PowerShell에서 다음처럼 설정한 뒤 서버를 시작합니다.

```powershell
$env:JUDGE_HOST = '0.0.0.0'
$env:JUDGE_ALLOWED_SUBNETS = '192.168.0.0/24'
python server.py
```

`JUDGE_ALLOWED_SUBNETS`를 실제 내부망 대역으로 바꾸세요. 학생은 로그인 화면에서 수업 코드를 입력합니다. 인터넷에 공개하려면 HTTPS를 제공하는 인증 프록시 또는 VPN 뒤에 두세요. 이 앱은 교육용 소규모 사용을 위한 것이며, Docker 자원 제한만으로 강한 다중 사용자 격리를 보장하지 않습니다.

같은 Wi-Fi/LAN에서만 접속시키려면 `powershell -File .\start-lan.ps1`로 시작합니다. 이 스크립트는 Wi-Fi 대역을 계산해 해당 대역과 로컬 PC에서만 응답합니다. 다른 기기에서는 `http://<이 PC의 Wi-Fi IP>:8000`으로 접속합니다. Wi-Fi IP가 바뀌면 서버를 다시 시작하세요.

## API

- `GET /api/problems`: 문제 목록과 예제
- `GET /api/weeks`: 주차 목록
- `POST /api/student/login`: `{"student_id":"00123","student_name":"김학생","class_code":"AS006"}`
- `POST /api/student/logout`: 현재 세션 종료
- `GET /api/student/me`, `GET /api/student/progress`: 현재 학생과 주차별 풀이 현황
- `GET /api/student/accepted-codes`: 로그인한 학생의 문제별 마지막 정답 제출 원문
- `POST /api/run`: 로그인 세션에서 `{"code":"print(input())","stdin":"hello\n"}`
- `POST /api/submit`: 로그인 세션에서 `{"problem_id":"sum-two","code":"a,b=map(int,input().split());print(a+b)"}`
- `POST /api/admin/weeks`: 주차 추가
- `POST /api/admin/problems`: 문제 및 예제/테스트 추가
- `POST /api/admin/students/import`: `.xlsx` 학생 명단 가져오기
- `GET /api/admin/students`: 학생 목록
- `GET /api/admin/submissions`: 최근 제출 목록
- `GET /api/admin/progress?query=&offset=0&week_id=week-10&sort=attempts&direction=desc`: 주차별 제출 현황(100명씩). 정렬 키: `student_id`, `name`, `attempts`, `accepted`; 정렬 방향: `asc`, `desc`. `week_id` 생략 시 전체 주차를 반환합니다.
- `GET /api/admin/class-code`: 현재 수업 코드 상태 조회
- `POST /api/admin/class-code`: `{"code":"새수업코드"}`로 수업 코드 변경

관리자 API에는 관리자 Bearer 토큰을 사용합니다. 학생 API에는 로그인 쿠키를 사용합니다.
